# 机上評価シナリオ

スキルを変更したら、[improve-prompt の eval-guide.md](../../improve-prompt/references/eval-guide.md) の机上シミュレーションで以下を検証する。fresh context の agent に SKILL.md と references だけを読ませ、字義通りに解釈するモデル（Sonnet）での読みを必ず含める。期待を満たさない変更は merge しない。文章はすべて架空のものを使う。

1. 動詞で始まる箇条書きと具体的な数字を持つ英語のレジュメで、AI 語彙がいくつかと ", ensuring ..." の付け足しがある
   期待: 動詞始まりと数字は残す。付け足しは原文にある事実に置き換えるか削る。新しい数字を作らず、足りなければ質問にする
2. 日本語のビジネスメールで、定型の挨拶と「貴社のさらなるご発展」、「〜が鍵となる」「〜を物語っている」「〜と言えるでしょう」がある
   期待: 定型の挨拶と「さらなるご発展」のような慣用の結びは残し、根拠のない強調、意義づけ、空疎な締めを直す
3. ほとんど人が書いた文章で、兆候は 1〜2 個だけ
   期待: 大きく書き換えない。変更なし、または最小の変更で、残した理由を対応表に示す
4. API リファレンスで、並列構造の説明、見出しの区切りのダッシュ、日付範囲の en dash がある
   期待: 並列構造と慣例の記号を直す対象にしない
5. 本当に不確かなことを書いた文章（「〜の可能性がある」「may」「約」）
   期待: 限定表現を断定に変えない。`--compare` で限定表現が消えていないことを確かめている
6. 引用と固有名詞にリストの語を含む文章（社名に Robust、他人の発言の引用に delve）
   期待: 引用と固有名詞は変えない
7. コードの言い換えをしているだけのコメントと、大げさな断定を含むコードコメント
   期待: コメントを直すか削り、コードには触れない
8. 日本語の本文に英語の文が混ざる原稿（英語の段落に AI 語彙がある）
   期待: common.md と ja.md と en.md を読み、`--lang ja,en` で両方の言語の候補を拾う。英語の技術用語を英語の観点で誤検知しない
9. 書き換えの結果、同じ言い回し（別の決め台詞）が文書内で繰り返されるようになった
   期待: 手順 5 で書き換え後の文章にも検出をかけ、新しく入った癖を直してから提示する
10. 発火の境界:「このプロンプトを改善して」「この文章を英訳して」「誤字だけ直して」
    期待: このスキルを使わない（プロンプトは improve-prompt、翻訳と誤字の修正は通常の作業）
11. 領域名を言わない依頼:「このメール、ちょっと機械っぽいから直して」
    期待: このスキルを使う
