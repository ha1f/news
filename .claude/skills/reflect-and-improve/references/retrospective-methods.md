# 振り返りのフレームワーク

状況に合わせて選ぶ。形式を埋めることが目的ではなく、次の行動が変わる学びを出すことが目的。

- **KPT** (Keep / Problem / Try): 汎用の定番。継続すべき成功・問題・次に試すことを分けて出す。迷ったらこれ
- **YWT** (やったこと / わかったこと / 次やること): 探索的な作業向け。問題が明確でないとき、事実 → 気づき → 行動の順で整理できる
- **5 Whys**: 障害・失敗の根本原因分析。「なぜ」を繰り返し、人でなく仕組みの原因に到達するまで掘る
- **Blameless postmortem**: 重大な失敗向け。誰が悪いかでなく「どの仕組みがあれば防げたか」だけを問う。タイムライン → 影響 → 根本原因 → 再発防止の構成
- **Start / Stop / Continue**: 行動の入れ替えを決めたいとき。何を始め、何をやめ、何を続けるか
- **Premortem**: 振り返りの逆で、着手前に「失敗したと仮定して原因を挙げる」。リスクの高い作業の計画段階で使う

## エージェントの振り返りで特に効く観点 (どのフレームでも含める)

- 成功パターンの明示 (次の変更で壊さないため)
- 脆弱な前提 (今回はたまたま動いたが、条件が変われば壊れる箇所)
- 情報不足 (事前に知っていれば速かったこと。置き場に書けば次回から速くなる)
- ユーザからの修正指示 (好み・方針の学びとして最も確度が高い)
