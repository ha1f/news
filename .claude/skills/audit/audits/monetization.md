# 収益化準備監査

- **監査ID**: monetization
- **目的**: 収益化（課金・広告いずれの形でも）の前に満たすべき法令・規約・表示の要件を棚卸しし、人間の判断が要る点を「整理された論点」の状態にしておく
- **対象**: references/sources/ の各ソース利用条件、サイトの表示（規約・プライバシーポリシー・運営者情報）、課金・広告・解析の導入計画（VISION.md の M5）

GUARDRAILS は「ソースの利用規約の整理は収益化前に人間が行う」と定める。この監査はその人間の判断を代行せず、判断に必要な材料（各ソースの条件・法令の要件・選択肢）を再現可能に揃える下準備を担う。

## 再監査トリガー

- M5（収益化）の着手前 — 必須
- ニュースソースの追加時（追加分の商用利用条件の確認）
- 広告・アクセス解析・課金手段を導入する PR
- 前回実施から6ヶ月以上経過（ソースの規約は変わる）

## チェックリスト

法令は e-Gov 法令検索（https://laws.e-gov.go.jp/）と消費者庁・総務省の公表資料、ソース条件は各ソースの規約ページを一次情報とする。

### ソース利用条件の棚卸し

- [ ] 全ソース（references/sources/*.md）について、RSS/API の利用規約・商用利用の可否・帰属表示要件を一次情報で確認し、各ソース定義の「利用条件」セクションと [data/monetization-sources.md](data/monetization-sources.md) の詳細（引用・横断整理）を更新する（前回確認日からの差分を見る）
- [ ] AI での処理に対する制限（生成 AI/RAG 利用の除外条項、robots.txt の AI クローラ拒否・Content-Signal）の有無を確認する。明示的に AI 利用を制限するソースは除外を提案する（オーナー方針 #241: AI 不可のソースは使わない。非営利の現状にも効く）
- [ ] 商用利用不可・要許諾のソースを特定し、収益化時の扱いの選択肢（除外・許諾申請・代替ソース）を整理する
- [ ] サードパーティ経由のソース（GitHubTrendingRSS 等）は、経由サービスと元サービスの両方の条件を確認する

### 課金導入時の要件

- [ ] 特定商取引法に基づく表記の要件（事業者名・所在地・連絡先・対価・支払時期・解約条件）を整理し、開示範囲の論点を人間に渡せる形にする
- [ ] 決済プロバイダの利用規約・禁止コンテンツ規定と本サービスの適合を確認する（契約自体は人間）
- [ ] 有料化の範囲と著作権法47条の5への依拠の関係を確認する（legal 監査と併走）

### 広告導入時の要件

- [ ] 景品表示法・ステルスマーケティング規制: 広告と編集コンテンツの区別表示の要件
- [ ] 広告と記事選定の独立性の方針整理（方針決定は GUARDRAILS が人間に留保。論点整理まで）

### 解析導入時の要件

- [ ] 外部送信規律（電気通信事業法）の公表事項の整理
- [ ] プライバシーポリシーの更新要否（legal 監査と併走）

## 人間に残す判断

- 収益化の形の決定と着手判断（VISION.md のフェーズ・マイルストーン判断）
- 決済プロバイダとの契約
- 商用利用不可ソースの除外・許諾申請の判断
- 事業者情報（氏名・住所等）の開示範囲
