# 法務・コンテンツ権利監査

- **監査ID**: legal
- **目的**: 配信コンテンツと法的文書が、法令・第三者の権利の観点で守れる状態にあるかを確認する
- **対象**: サイトの法的文書と説明文（terms.md / privacy.md / about.md）、配信の実装と実物（curate-news の SKILL.md・`_posts/` の出力・公開サイト）、references/sources/ のソース定義

この定義は issue [#166](https://github.com/ha1f/news/issues/166) で実施したアドホックな法務レビュー（競合調査・法務観点レビュー・実装実態との突合）を再現可能にしたもの。個別指摘の経緯は同 issue のコメントを参照。

## 再監査トリガー

- terms.md / privacy.md / about.md の文面を変更する PR（理想はマージ前、事後でも可）
- 配信フォーマットの変更（要約の構造・厚さ・画像の扱いが変わる変更）
- 収集・表示するデータが増える機能（解析・フォーム・コメント等）の導入
- 収益化（課金・広告）の着手前 — monetization 監査と併走
- 関連法令の改正・新しい規制を知ったとき
- 前回実施から6ヶ月以上経過

## チェックリスト

法令の条文は e-Gov 法令検索（https://laws.e-gov.go.jp/）、著作権の解釈は文化庁、個人情報は個人情報保護委員会（https://www.ppc.go.jp/）を一次情報とし、現物と突合する。

### 配信コンテンツの権利（著作権法）

- [ ] 要約・リード・読みどころが事実と論点の抽出に留まり、原文の構成・修辞をなぞる詳細要約・逐語訳になっていないか（翻案リスク。GUARDRAILS「コンテンツの権利ガードレール」と直近の出力数件を突合）
- [ ] 記事本文・記事画像の転載が無いか（出力とテンプレートの実物確認）
- [ ] 47条の5（軽微利用）に依拠する場合、施行令・施行規則の要件を実装が満たしているか: 軽微性、robots.txt の尊重、ペイウォール記事の非利用、連絡先の明示
- [ ] 見出しの日本語リライトが原題の創作的表現を引き写していないか
- [ ] フィード経由で取得・保持している情報の範囲（全文配信フィードは本文も含む）が、法的文書の記載と一致しているか

### 法的文書（利用規約・プライバシーポリシー）

- [ ] 文面が実装の実態（収集データ・処理・第三者サービス）と一致しているか
- [ ] 法的評価の断定的宣言（「翻案ではない」等）が無いか — 事実の記述（掲載形式・収集方法・目的）に留める
- [ ] 免責が全部免責になっていないか（消費者契約法8条: 事業者の故意・重過失の免責条項は無効）
- [ ] 規約変更条項が民法548条の2・548条の4の要件（変更の合理性・効力発生時期・事前周知）を満たすか
- [ ] 禁止事項が包括表現でなく具体的な列挙になっているか
- [ ] 個人情報保護法の公表事項（32条）、開示等請求・苦情の窓口が記載されているか。解析・広告を導入する場合は外部送信規律への対応
- [ ] 権利者からの削除・訂正の申出窓口が明示され、実際に連絡できる導線があるか
- [ ] サイト内の記述間に矛盾が無いか（例: about の訴求文と規約の目的規定）

### ソースとの関係

- [ ] 各ソースのフィード利用が当該ソースの利用規約・robots.txt に反していないか（新規追加ソースを中心に references/sources/ と突合。商用利用条件の棚卸しは monetization 監査が担う）

## 人間に残す判断

- 法的文面の最終承認（#166 の受け入れ条件「オーナーが内容を確認・承認済み」）
- 法的リスクの受容判断（解釈が分かれる論点をどちらに倒すか）
- 弁護士への相談の要否と依頼
- 運営者情報（氏名・住所・連絡先）の開示範囲
