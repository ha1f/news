# 机上評価シナリオ

スキルを変更したら、[improve-prompt の eval-guide.md](../../improve-prompt/references/eval-guide.md) の机上シミュレーションで以下を検証する。fresh context の agent に SKILL.md と references だけを読ませ、字義通りに解釈するモデル（Sonnet）での読みを必ず含める。期待を満たさない変更は merge しない。素材はすべて架空のものを使う。

1. 「来週の部長会で、問い合わせ対応の自動化ツールの試験導入を承認してもらいたい。資料を作って」。素材は問い合わせ件数の内訳と見積もり
   期待: 手順 1 で、届け方（会議で画面を一緒に読むなら読み物）と出力形式を確かめるか、仮定を書く。目的は「決める」。冒頭に判断してほしいことと推奨を置き、選択肢・リスク・次の一手・アペンディックスを含める。ルールシートを書く前にスライドを作り始めない
2. 「カンファレンスで 20 分話す。テーマは社内の開発者体験の改善。スライドを作って」
   期待: 投影・動かす。枚数を持ち時間から逆算し、発表者ノートを必須にし、話す文の全文をスライドに載せない。中核メッセージを冒頭で予告し、末尾で結論として言い直す
3. 「新人研修の資料を作って。研修で映すし、あとで配布もしたい」
   期待: 一つのデッキで両方の密度を狙わない。研修で話すなら投影を主にし、配布の用途は発表者ノートか別の文書で満たすと決めて、ルールシートの仮定に書く
4. 「このスライドのタイトルが微妙。直して」。タイトル「導入の手間は減った。でも、差は広がっている」、図は利用頻度の分布が二つの山に分かれたもの、図の下に「利用は二極化している」というキャプション
   期待: ルールシートを復元する（届け方が読み取れなければ聞く）。T2・T4・T10 で不合格を出す。重要度を付けて「二極化」を最上位に選び、図の形（分布）と一致させる。限定や母数を外すなら補足行か注記に残す（T7）
5. 「説得力が出るように、業界の数字を入れておいて」。素材に業界の数字はない
   期待: 数字を作らない。「要確認」にして、出典のある数字をユーザーに求める
6. 描画に pptx スキルを使う環境で、pptx スキルが「全スライドに視覚要素」「丸背景のアイコン」を勧めている
   期待: visuals.md の既定（頼まれていない装飾を足さない、短い列挙は箇条書きのまま）を優先する
7. 会社のテンプレートにタイトル下の線が入っている
   期待: 外部規定としてルールシートに書き、テンプレートに従う。V7 で不合格にしない
8. 英語のデッキ（投資家向けピッチ、10 分）
   期待: 同じ手順で進める。タイトルの長さは英語の目安（1 行）、枚数はピッチの目安を参考に持ち時間から逆算する
9. 「プレゼンの構成だけ相談したい。スライドはまだいらない」
   期待: 手順 1〜3 で止め、ルールシートとタイトル列までの設計書を返す。描画しない
10. 発火の境界:「この pptx からテキストを全部抜き出して」「この報告書の AI っぽい言い回しを直して」
    期待: このスキルを使わない（pptx の機械的な操作、文章の AI っぽさの修正は対象外）
11. 領域名を言わない依頼:「明日の定例で見せる進捗、何枚かにまとめておいて」
    期待: このスキルを使う。目的は「伝える」
