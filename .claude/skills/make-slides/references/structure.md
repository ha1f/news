# デッキの構成

構成はソフトを開く前に、文字だけで決める。手順は流派をまたいで一致している（Duarte、Knaflic、Reynolds、Atkinson、Doumont、前田、伊藤、元マッキンゼー社員のブログ）。根拠は規範と経験則で、デッキ構成の効果を測った実証研究は見つかっていない。

## 中核メッセージ

デッキ全体で聞き手に持ち帰ってほしいことを 1 文にする。

- 視点（自分の主張）、懸かっているもの（聞き手が受け入れた場合と受け入れなかった場合に何が起きるか）、求める行動の三つを含める（Duarte の Big Idea、Knaflic）
- スライドなしで短く言えるか試す（Knaflic は 3 分、伊藤と前田は 1 分）。言えなければ、まだ中身が決まっていない
- 悪い例:「本資料では市場動向、顧客調査、価格、今後の進め方を説明します」（目次の読み上げ）
- 良い例:「問い合わせの 6 割を占める 3 種類に絞って自動応答を入れれば、来期の増員なしで応答時間を半分にできるので、来月から試験導入を承認してほしい」

## 素材の仕分け

素材を事実（何が起きているか）、解釈（それが何を意味するか）、行動（だから何をするか）に分ける（空・雨・傘）。根拠が素材にある主張と、ない主張に印を付ける。根拠のない主張は「要確認」にし、数字を補って埋めない。

## ドットダッシュ

主張の文（ドット）と、それを支える根拠（ダッシュ）だけでストーリーラインを書く（元マッキンゼー社員のブログ）。並べ方は一つに決め打ちせず、いくつか試してから選ぶ（Knaflic）。導入が要るなら、聞き手が同意している状況 → 起きた問題 → 聞き手が抱く問い → 答え（SCQA、Minto）の順に書く。

## タイトル列（ゴーストデッキ）

各スライドについて、設計書に次の 3 つをまず書く。ほかの欄は手順 4 で埋め、見た目はまだ作らない。

1. 答える問い: このスライドが答える読み手の問いを 1 つ
2. タイトル: その問いへの答え（[titles.md](titles.md)）
3. 証拠: 置く図やデータと、比較の種類（[visuals.md](visuals.md)）

答える問いが 1 行で書けないスライドと、なくても聞き手の判断や理解が変わらないスライドは、分ける、ほかと統合する、アペンディックスに移す、削る、のどれかにする（Umbrex）。

## 目的別の並び

ルールシートの目的で既定の並びを選ぶ。すべて実務家の型で、聞き手や社内ルールに合わせて変えてよい。変えたら理由を設計書に書く。

| 目的 | 並び | 出典 |
|---|---|---|
| 決める | エグゼクティブサマリー（判断してほしいことと推奨）→ 背景（最小限）→ 選択肢と比較 → 推奨と理由 → リスクと対策 → 次の一手 → アペンディックス | Umbrex、前田、Atkinson |
| 伝える | 要点のまとめ → 事実 → 解釈 → 示唆と次の一手 → アペンディックス | Umbrex、空・雨・傘 |
| 伝える（学術発表の慣習に従うとき） | 背景 → 目的 → 本論 → 結論 → 今後の課題。結論が目的に答えているかを確かめる | 東北大のチェックリスト |
| 教える | 地図（論点は理想 3 つ、多くて 5 つ）→ 1 枚 1 概念で論点ごとに説明 → 振り返り → 結論 | Doumont |
| 動かす | 注意を引く導入 → なぜ今大事か → 中核メッセージの予告 → 論点（理想 3 つ、多くて 5 つ）とつなぎ → 振り返り → 結論 → 締め | Doumont |

アジェンダやまとめのスライドは、目次の羅列ではなく、後に続く主張の要約にする。エグゼクティブサマリーは、本編のセクション（短いデッキならタイトル）と同じ順で対応させ、サマリーだけで結論、理由、求める判断がわかるようにする（Knaflic の水平ロジック、Umbrex）。

## 合格条件

| ID | 条件 | 判定 | 考え方 |
|---|---|---|---|
| D1 | タイトルだけを順に読むと話が通り、1 段落に要約でき、その要約が中核メッセージと一致する | 文脈を持たないサブエージェントに読ませる（SKILL.md 手順 3） | 1・6 |
| D2 | すべてのスライドで、答える問いが 1 行で書けている。なくても聞き手の判断や理解が変わらないスライドが本編にない | 設計書を見る | 1 |
| D3 | エグゼクティブサマリーがあれば、項目が本編のセクションかタイトルと同じ順で対応し、サマリーだけで結論・理由・求める判断がわかる | 設計書を見る | 1 |
| D4 | 決める・伝えるデッキで、観察だけで終わるスライドがなく、「だから何か」と「次に何をするか」がデッキ内にある | LLM | 1 |
| D5 | 決める・伝えるデッキで、懐疑的な聞き手が突きそうな点と、聞き手が判断に必要とする事実（費用、期限、リスクなど）を書き出し、すべてに本編かアペンディックスで答えている | LLM | 1・3 |
| D6 | 枚数と結論の位置がルールシートどおり。外れるなら理由が設計書にある | 設計書を見る | 1・4 |
| D7 | ストーリーラインの主張のうち、素材に根拠がないものがすべて「要確認」になっている | 素材と照合 | 3 |
| D8 | アジェンダや地図があれば、後に続く主張の要約になっていて、項目は多くて 5 つ（数は目安） | 設計書を見る | 1 |
| D9 | 本文から移した中身（発表者ノート、アペンディックス、注記へ）が移し先に実在する。読み物では発表者ノートを移し先にしていない | 手順 6 で設計書と描画物を照合 | 4 |
| D10 | ルールシートの聞き手の役（役職、前提知識）だけを与えた文脈のない読み手に、聞き手が受け取るもの（読み物はスライド、投影はスライドと発表者ノート）を渡し、読んだ後に取れる行動、足りない情報、意味のわからない語を書かせる。ルールシートの「聞いた後の行動」が取れ、意味のわからない語が残っていない | 手順 6 でサブエージェントに読ませる | 1・6 |
