# モードとルールシート

デッキを作る前に、届け方と目的を一つずつ選び、それに応じたルールシートを確定する。専門家の意見が割れる論点（スライドは単体で読めるべきか、結論は冒頭か末尾か、タイトルは完全文か見出しか、文字はどこまで減らすか）の多くは、想定しているモードの違いから来ている。モードを決めればどちらの意見を採るかが決まる。

出典の略称は [sources.md](sources.md) で引ける。根拠の種類は「実証」（統制実験）、「規範」（組織や教育機関のルール）、「経験則」（実務家個人の主張）で示す。

## 届け方（一つ選ぶ）

| 届け方 | 状況 | スライドの役割 |
|---|---|---|
| 投影 | 話し手が映しながら話す（発表、講演、研修、ピッチ） | 話を補う。詳細は発表者ノートか別資料に置く |
| 読み物 | 話し手なしで読まれる（事前配布、提案書、報告書、共有資料）。会議で全員が画面や手元の資料を読みながら議論する場合もここ | 1 枚で意味が通る。主張タイトルと根拠を同じスライドに置く |

- 「投影もするし配布もする」と言われたら、どちらで失敗すると困るかで主を一つ決める。もう一方の用途は、発表者ノート、アペンディックス、別の文書で満たす。一つのデッキで両方の密度を狙うと、スライドとしても文書としても機能しない（Reynolds の slideument、Duarte の Slidedocs）
- 黙読の時間が取れる意思決定や技術的な議論では、スライドより文章のほうが向く（Amazon の物語形式のメモ、Tufte）。スライドを頼まれたら作るが、そう判断したら一言提案する
- 投影でも、タイトルは話し手なしで主張が読めるように書く。スライドは写真に撮られたり後で配られたりして、話し手抜きで読まれる

## 目的（一つ選ぶ）

複数の目的がある場合は主目的を一つ選ぶか、デッキを分ける。

| 目的 | 聞いた後に聞き手がすること | 例 |
|---|---|---|
| 決める | 承認する、選択肢から選ぶ | 決裁、投資判断、提案 |
| 伝える | 事実と解釈を共有し、次の一手に合意する | 進捗報告、調査結果の共有 |
| 教える | 理解し、自分でできるようになる | 研修、講義、技術解説 |
| 動かす | 考えに共感し、支持や行動に移る | カンファレンス講演、LT、ピッチ |

## ルールシートの項目と既定値

設計書の冒頭に、次の項目を埋めたルールシートを書く（ひな形は [plan-template.md](plan-template.md)）。既定値はモードの組み合わせで決まる。ユーザーの指示、テンプレート、社内ルールがあればそちらを書く。

| 項目 | 投影 | 読み物 |
|---|---|---|
| 聞き手 | 役職、前提知識、いまどう考えているか | 同左 |
| 聞いた後の行動 | 目的から決まる。決めるなら Yes/No にできる依頼の形で書く | 同左 |
| 中核メッセージ | 1 文（[structure.md](structure.md)） | 同左 |
| 枚数 | 持ち時間から逆算する。目安は学術発表で 1 枚 30 秒〜1 分、決裁で 5〜9 枚・3 分（前田）、ピッチで 10 枚・20 分（Kawasaki）。いずれも経験則か規範 | 枚数の目標は置かない。主張の文の数がおおよその枚数になる（Umbrex） |
| 結論の位置 | 目的別の並び（[structure.md](structure.md)）に従う | 冒頭（エグゼクティブサマリー）。教えるなら冒頭で何がわかるかを示す |
| タイトル | 主張を 1 行で。日本語は 15 字前後を超えたら短縮を検討し、収まらなければタイトル＋補足行の二層にする（前田の 13＋40、Yahoo!ニュースの 15.5 字）。英語は 1 行 | 主張を 2 行以内の文で。英語は 15 語以内（Slideworks） |
| 本文の文字量 | 話す文の全文を載せない。載せるのは 2〜3 語のラベルと図（Mayer の冗長性原則） | 1 枚で意味が通る文。ただし 1 枚 1 メッセージ |
| 図 | 概念・過程・因果・データの主張には図を置く。短い列挙は箇条書きのまま | 同左 |
| 発表者ノート | 必須。話す内容と、スライドに載せない詳細を書く | 不要 |
| アペンディックス | 決める・伝えるなら置き、想定される質問の根拠を入れる | 同左 |
| 文字サイズ | 本文 18pt 未満を使わず、なるべく 24pt 以上。タイトル 28pt 以上（Alley 系のチェックリスト。名古屋大は本文 28pt・見出し 36pt、Kawasaki は 30pt 以上と、値は出典で割れる） | 段階を 2〜3 に絞り、想定する画面や印刷で読める大きさにする（数値の出典なし） |
| 書体・色・装飾 | [visuals.md](visuals.md) の既定 | 同左 |
| 出力形式 | ユーザーの指定。なければ聞く | 同左 |
| 優先する外部規定 | テンプレート、ブランド規定、社内ルール | 同左 |

目的ごとに必ず含めるスライドと並びは [structure.md](structure.md) の「目的別の並び」にある。

## モードが混ざったときの失敗

ルールシートを決めずに作ると、次のように混ざりやすい。手順 6 でも確かめる。

- 投影なのに読み物の文字量: 聞き手が読むのに追われて話を聞かない
- 読み物なのに投影の短さ: 話し手がいないと何を言いたいかわからない（日本で「紙芝居」と批判される資料）
- 決めるデッキで結論が末尾: 決裁者が途中で割り込み、判断の材料が最後まで揃わない
- 一つのデッキに複数の目的: どのスライドも何のためにあるのかがぼやける
