# 設計書のひな形

設計書は出力形式に依存しないデッキの中身で、描画の元になる。手順 1 で作り、手順 6 の判定結果も書き込む。項目名は変えない。手順 3 の時点ではスライドごとに「答える問い」「タイトル」「証拠」だけを書き、残りの欄は空けておく。「なし」は該当しない欄にだけ書く。

```markdown
# <デッキの仮タイトル> 設計書

## ルールシート

- 届け方: 投影 / 読み物
- 目的: 決める / 伝える / 教える / 動かす
- 聞き手: <役職、前提知識、いまどう考えているか>
- 聞いた後の行動: <決めるなら Yes/No にできる依頼の形で>
- 中核メッセージ: <1 文>
- 持ち時間と枚数: <例: 20 分、10〜13 枚>
- 結論の位置: <冒頭 / 冒頭で予告し末尾で結論 / 末尾>
- タイトルの長さ: <例: 1 行、15 字前後で警告、超えたら補足行>
- 本文の文字量: <例: ラベルと図のみ、詳細は発表者ノート>
- 発表者ノート: 必須 / 不要
- アペンディックス: あり / なし
- 文字サイズの最小: <例: 本文 24pt、タイトル 28pt>
- 出力形式: <例: pptx。描画を頼まれていなければ「未定」>
- 優先する外部規定: <テンプレート、ブランド規定、社内ルール。なければ「なし」>
- 仮定: <ユーザーに確かめずに決めた項目と、その理由>

## 素材の仕分け

- 事実: ...
- 解釈: ...
- 行動: ...
- 要確認: <根拠が素材にない主張>

## ストーリーライン（ドットダッシュ）

- <主張の文>
  - <根拠>

## スライド

### 1
- 答える問い: ...
- タイトル: ...
- 補足行: <なければ「なし」>
- 書き出しと重要度: <要素: 点数 を並べる>
- 証拠: <図やデータと、比較の種類>
- 本文: ...
- 発表者ノート: ...

## 検証結果

| ID | スライド | 合否 | メモ |
|---|---|---|---|
```
