# make-slides

聞き手が判断・理解・行動できるデッキを、最初の出力で出す。スライドの作り方は届け方（投影して話すか、読まれるか）と目的（決める・伝える・教える・動かす）で変わり、違う作法が混ざるとどちらとしても機能しなくなる。そこで、作る前にこのデッキのルールを確定し、そのルールの下で作る。できたものから AI っぽさを後で消す工程には頼らない。

| ファイル | 中身 | 読むとき |
|---|---|---|
| [references/modes.md](references/modes.md) | 届け方と目的の分け方、ルールシートの項目と既定値 | 手順 1 |
| [references/structure.md](references/structure.md) | 中核メッセージ、ドットダッシュ、タイトル列、目的別の並び | 手順 2〜3 |
| [references/titles.md](references/titles.md) | タイトルの決め方 | 手順 3〜4 |
| [references/visuals.md](references/visuals.md) | 図・データ・書体・色・装飾 | 手順 4〜5 |
| [references/plan-template.md](references/plan-template.md) | 設計書のひな形 | 手順 1 |
| [references/sources.md](references/sources.md) | 出典と根拠の種類 | 根拠を聞かれたとき |

各 reference のルールには ID 付きの合格条件がある。作るときはこの条件を満たすように作り、手順 6 で同じ条件を合否で判定する。作る基準と確かめる基準を分けない。

## 守ること

- 素材にない事実・数字・引用を作らない。足りなければ設計書に「要確認」と印を付けてユーザーに聞く
- ルールシートを確定するまでスライドを作らない。途中で聞き手・目的・届け方が変わったらルールシートを書き直し、影響する手順からやり直す。二つのモードの中間を取る折衷はしない
- ユーザーや組織のテンプレート、ブランド規定、社内の資料ルールがあれば references の既定値より優先し、ルールシートに書く
- 描画に別のスキルやテンプレート（pptx スキルなど）を使うときも、見た目の判断はルールシートと visuals.md に従う。描画側の推奨（全スライドに視覚要素、丸背景のアイコン、タイトル下の線など）とぶつかったらこちらを取る

## 手順

1. **ルールを確定する**: modes.md を読み、依頼と素材からルールシートを埋める。設計書を plan-template.md のひな形で作り、冒頭にルールシートを書く。置き場所はユーザーの指定に従い、なければ作業ディレクトリに置く（成果物をファイルで出すならその隣）。決められない項目のうち結果を大きく変えるもの（届け方、目的、聞き手、出力形式）だけをまとめて一度聞く。それ以外の項目と、聞けない状況での項目は仮定を書いて進め、納品時に仮定を示す
2. **中核メッセージと素材**: structure.md に従い、デッキ全体の主張を 1 文にし、素材を事実・解釈・行動に仕分ける
3. **骨組みを作る**: ドットダッシュでストーリーラインを書き、タイトル列（各スライドの「答える問い」「タイトル」「証拠と比較の種類」）を設計書に並べる。タイトルだけを通読して直す。この段階では見た目を作らない。構成やタイトルだけの相談なら、ここまでの設計書を納品する
4. **1 枚ずつ詰める**: titles.md の手順でタイトルを確定し、visuals.md に従って図を選び、本文と発表者ノートをルールシートの文字量で書く
5. **描画する**: ルールシートの出力形式で描画する。その形式を扱うスキルやツールが使える環境ならそれを使う。設計書は形式に依存しないので、形式を変えるときは手順 5 だけをやり直す。描画した全スライドを画像にして見る（HTML はブラウザのスクリーンショット、pptx は LibreOffice で PDF にしてから画像に、など）
6. **検証する**:
   - 各 reference の合格条件（D・T・F・V）を全スライドで合否判定する。点数は付けない
   - タイトル列（補足行を含む）だけを、このデッキの文脈を持たないサブエージェントに渡し、各スライドに何が載っていそうかとデッキの結論を書かせる。結論が中核メッセージと違えば、ずれたタイトルを直す（サブエージェントを使えない環境では省き、納品時にそう書く）
   - 不合格は該当する手順に戻って直し、直した箇所を判定し直す
7. **納品する**: 成果物に次を添える
   - ルールシート（仮定したものは仮定と書く）
   - 検証結果。不合格のまま残したものはその理由
   - 人に返す判断（「要確認」の事実、タイトルから外した限定をどこまで残すか、など）

## 既存のスライドを直す・レビューするとき

デッキからルールシートを復元する。届け方と目的が読み取れず、それで直し方が変わるなら聞き、変わらないなら仮定を書く。手順 6 の判定から始め、不合格の項目を手順 2〜5 の該当箇所に戻って直す。レビューだけを頼まれたら直さず、不合格の項目と直し方の案を返す。
