# make-slides

聞き手が判断・理解・行動できるデッキを、最初の出力で出す。スライドの作り方は届け方（投影して話すか、読まれるか）と目的（決める・伝える・教える・動かす）で変わり、違う作法が混ざるとどちらとしても機能しなくなる。そこで、作る前にこのデッキのルールを確定し、そのルールの下で作る。できたものから AI っぽさを後で消す工程には頼らない。

| ファイル | 中身 | 読むとき |
|---|---|---|
| [references/modes.md](references/modes.md) | 届け方と目的の分け方、ルールシートの項目と既定値 | 手順 1 |
| [references/plan-template.md](references/plan-template.md) | 設計書のひな形 | 手順 1 |
| [references/structure.md](references/structure.md) | 中核メッセージ、ドットダッシュ、タイトル列、目的別の並び | 手順 2〜3 |
| [references/titles.md](references/titles.md) | タイトルの決め方 | 手順 3〜4 |
| [references/visuals.md](references/visuals.md) | 図・データ・書体・色・装飾・描画後の確認 | 手順 4〜6 |
| [references/sources.md](references/sources.md) | 出典と根拠の種類 | 根拠を聞かれたとき |

各 reference のルールには ID 付きの合格条件がある。作るときはこの条件を満たすように作り、決まった時点で同じ条件を合否で判定する。作る基準と確かめる基準を分けない。

## 守ること

- 素材にない事実・数字・引用を作らない。足りなければ設計書に「要確認」と印を付けてユーザーに聞く。調べて足すなら出典を付け、それも「要確認」にする
- ルールシートを確定するまでスライドを作らない。途中で聞き手・目的・届け方が変わったらルールシートを書き直し、影響する手順からやり直す。二つのモードの中間を取る折衷はしない
- ユーザーや組織が指定したテンプレート、ブランド規定、社内の資料ルールは references の既定値より優先し、ルールシートに書く
- 描画に汎用のスキルや既定のテンプレート（pptx スキルなど）を使うときも、見た目の判断はルールシートと visuals.md に従う。描画側の推奨（全スライドに視覚要素、丸背景のアイコン、斜体のアクセント、全面のダーク背景など）とぶつかったらこちらを取る

## 依頼の範囲

| 依頼 | 行う手順 | 設計書 |
|---|---|---|
| 新しく作る | 1〜7 | ファイルに書く |
| 構成やタイトルだけの相談（一部のスライドだけも含む） | 1〜3 と、手順 4 のうちタイトルの確定。図・本文の作り込みと描画はしない。判定は D と T | 返答の中に書いてよい |
| 既存のスライドを直す | 下の「既存のスライドを直す・レビューするとき」 | 直す範囲が数枚なら返答の中に書いてよい |
| レビューだけ | 同上。直さずに、不合格の項目と直し方の案を返す | 作らない。判定表は返答に書く |

## 手順

1. **ルールを確定する**: modes.md を読み、依頼と素材からルールシートを埋める。聞くのは、依頼と素材から決められず、結果を大きく変える項目だけにし、まとめて一度で聞く
   - 届け方と目的は modes.md の見分け方で決め、決められなければ聞く
   - 聞き手は役職と前提知識がわかればよく、残りは仮定する
   - 出力形式は描画（手順 5）まで頼まれているときだけ聞く
   - 素材がテーマだけなら、主張したいことと根拠になる事実を同じ質問で聞く。答えがなければ骨組みまで作り、中身は「要確認」にする
   - 聞けない状況（任せると言われた、無人で実行している）では仮定を書いて進める。仮定はすべてルールシートに書き、納品時に示す
   - 設計書は plan-template.md のひな形で作り、冒頭にルールシートを書く。ファイルにするなら、ユーザーの指定がなければ成果物と同じ場所（成果物がファイルでなければ作業用の一時ディレクトリ）に置き、納品時に場所を伝える
2. **中核メッセージと素材**: structure.md に従い、デッキ全体の主張を 1 文にし、素材を事実・解釈・行動に仕分ける
3. **骨組みを作る**: structure.md に従ってストーリーラインとタイトル列を設計書に書く。見た目はまだ作らない
   - D 群を判定し、不合格を直す。D1 の通読は、タイトル列（補足行があれば含む）だけをこのデッキの文脈を持たないサブエージェントに渡し、各スライドに何が載っていそうかとデッキの結論を書かせて、中核メッセージと照合する（サブエージェントを使えない環境では自分で読み、納品時にそう書く）
   - ユーザーと対話できる新規作成なら、ここで設計書（ルールシート、ストーリーライン、タイトル列）を見せ、ずれを直してもらってから手順 4 に進む。任されているなら見せずに進む
4. **1 枚ずつ詰める**: titles.md の手順でタイトルを確定し、visuals.md に従って図を選び、本文と発表者ノートをルールシートの文字量で書く。T 群と、設計書で判定できる F 群（F3〜F5）を判定し、不合格を直す
5. **描画する**: ルールシートの出力形式で描画する。その形式を扱うスキルやツールが使える環境ならそれを使う
   - 描画の前に、テーマ（タイトルの位置、書体、文字サイズ、色、余白）を一度だけ決め、マスターやテーマ定義に置く。各スライドはそこへ中身を流し込み、スライドごとに見た目を考えない。編集できる形式なら、スライドを画像だけにしない
   - 設計書は形式に依存しないので、形式を変えるときは手順 5 からやり直す
6. **検証する**: 全スライドを画像にし、visuals.md の「描画後の確認」に従って V 群と、画像で見る F 群（F1・F2）を判定する
   - 条件の対象外（D5 は決める・伝えるデッキだけ、V1 は投影だけ、など）は「対象外」と書く。画像を作れなかった条件は、設計書や描画データで判定できる範囲で判定し、残りは「未判定」と書く
   - 不合格は該当する手順に戻って直す。直した表現や数字は、デッキ全体（サマリー、アペンディックス、発表者ノート）で同じ箇所を探して揃え、直した箇所を判定し直す
7. **納品する**: 成果物に次を添える
   - ルールシート（仮定したものは仮定と書く）
   - 検証結果。不合格・未判定のまま残したものはその理由
   - 人に返す判断（「要確認」の事実、タイトルから外した限定をどこまで残すか、など）

## 既存のスライドを直す・レビューするとき

デッキからルールシートを復元する。届け方と目的が読み取れず、それで直し方が変わるなら聞き、変わらないなら仮定を書く。対象のスライドについて titles.md の決め方の手順 1〜3（問い、書き出し、重要度）を行ってから判定する（T3 と T7 はこれがないと判定できない）。不合格の項目は手順 2〜5 の該当箇所に戻って直す。1〜数枚だけが対象なら、判定は D 群を除いた T・F・V にする。
