# プロファイル1件分のキュレーション

取得済みのキャッシュから、1つの読者プロファイルに向けて記事を選び、出力して保存するまでの手順。SKILL.md のステップ4から subagent に渡される。

前提として渡されるもの: プロファイルID、好みファイル（`.claude/skills/curate-news/profiles/{プロファイルID}.md`）のパス、取得済みのソース・カテゴリの一覧。

## 1. 候補を絞る

まず、このプロファイルの過去の掲載記事を取得する（履歴はプロファイルごとに独立。他のプロファイルに載った記事は載せてよい）:

```bash
python3 .claude/skills/curate-news/scripts/recent_urls.py --profile {プロファイルID}
python3 .claude/skills/curate-news/scripts/recent_topics.py --profile {プロファイルID}
```

- URLリストはこのステップ以降の除外対象とする
- ヘッドラインはトピック重複チェックに使う

次に、渡されたソース・カテゴリを `--show-cache-summary` で一覧表示する:

```bash
python3 .claude/skills/curate-news/scripts/fetch_feeds.py --source hatena --category テクノロジー --show-cache-summary
# 渡された全ソースに対して同様に実行（並列可）
```

タイトル・URL・スコアから候補を30件程度に絞る。この段階では:

1. 同じURLの記事を1つにまとめる（重複排除）。過去掲載URLに一致する記事も除外する
2. **トピック重複チェック**: 候補のタイトルを掲載済みヘッドラインと照合し、同一トピック（同じ事件・発表・出来事）の記事を検出する。URLが異なっても、別ソース・別角度で同じ話題を扱う記事は重複とみなす
   - 重要な新事実や進展がある続報のみ残し、読みどころに「続報」と明記する
   - 単なる別ソースからの焼き直し（新情報なし）は除外する
3. 好みファイルの「読みたくない記事」に該当するものを除外する
4. 「興味・関心」との関連度、スコアから有力候補を選ぶ

## 2. description を読んで最終選定

候補が含まれるキャッシュJSON（ソース・カテゴリ単位のファイル）をReadツールで読み、候補記事の `description` を確認して最終的な記事を10件程度に決定する。1つのキャッシュファイルに複数の候補が含まれる場合はまとめて読む。

多様性の担保:
- 同カテゴリからは2件までにする。読んでいて飽きないよう、ジャンルを散らす
- **セレンディピティ枠**: 興味・関心に直接マッチしない記事も1〜2件、意図的に混ぜて視野を広げる。意外でも「読んでよかった」と思える質の記事を選ぶ

## 3. 出力

海外ニュースも含めて全て日本語で出力する。表現は [.claude/GUARDRAILS.md](../../../GUARDRAILS.md) のコンテンツの権利ガードレールに従う。

```
## ニュース ({取得日時} JST)

{リード — 2〜3文}

1. [{見出し}]({URL}) ({ソース名})<br>
   {読みどころ — 1文}

2. [{見出し}]({URL}) ({ソース名})<br>
   {読みどころ — 1文}

...
```

言葉づかいの水準（専門用語をそのまま使うか、噛み砕くか）は好みファイルの「読者像」に合わせる。

### リード（冒頭の概況）

新聞の1面リードのように、読者を引き込む役割を果たす。

- 具体的なファクト（固有名詞・数字・出来事）から書き始める。読者が「今日何が起きているか」を一文で掴めるように
- 全記事を俯瞰した上で、今日の空気感をコンパクトに伝える
- 2〜3文。体言止めや短文を活用してリズムよく

### 各記事の見出し

読者目線で編集する。

- 何が起きたのか・何が面白いのかが見出しだけで伝わるように
- 長いタイトルはエッセンスを残して短縮する（目安30字以内）
- 英語記事は日本語の見出しとして自然な表現にする
- 元タイトルが既に良ければそのまま使ってよい

### 読みどころ（各記事の補足）

見出しだけでは伝わらない「この記事を開く理由」を1文で添える。

- 20〜40字程度。「読んだら何がわかるか」の観点で書く
- descriptionが空や見出しとほぼ同内容のソースでは、見出しと差別化できないため省略してよい

### 記事の並び順

「読む体験」として面白い流れを設計する。

- 1本目は最もインパクトのある記事で引き込む
- 隣り合う記事にゆるい文脈のつながりを持たせる
- 終盤に興味外ジャンルの意外性のある記事を配置すると余韻が残る

### その他

- スコアはキュレーション時の内部判断に使い、出力に含めない
- ソース名はソース定義の「表示名」を使う

## 4. 保存

`{YYYY-MM-DD}` は JST (Asia/Tokyo) 基準の日付とする。推測せず、以下のコマンドで取得する:

```bash
TZ=Asia/Tokyo date +%F
```

出力先: `.claude/skills/curate-news/output/{YYYY-MM-DD}-{プロファイルID}.md`
同じ日・同じプロファイルで複数回実行した場合は上書きする。

保存したパスと、選定した記事数・見出しの要約を呼び出し元に返す。
