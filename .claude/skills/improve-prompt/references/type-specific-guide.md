# プロンプト種類別の改善ガイド

対象プロンプトの種類に応じて、以下の観点を追加で確認する。
全てを適用する必要はなく、対象プロンプトに関連するものだけを選んで使う。

## エージェント向けプロンプト

エージェント向けプロンプトは、長時間の自律動作を前提とするため、通常のプロンプトとは異なる観点が重要になる。

### 自律性と安全性のバランス

破壊的操作（ファイル削除、force push、外部サービスへの投稿など）の前に確認を求める指示があるか。取り返しのつかない操作とローカルで可逆な操作を区別し、後者は自律的に進められるようにする。

### 状態管理

長時間のタスクでは、コンテキストウィンドウのコンパクションや切り替えが発生する。進捗をファイルやgitに保存する指示があるか。構造化データ（JSON等）はスキーマの一貫性を保つ。自由記述のメモは非構造化テキストで十分。

### オーバーエンジニアリングの抑制

Claude 4.5/4.6は要求以上のことをやりがちで、不要なファイル作成、過剰な抽象化、求められていない機能追加をすることがある。「現在のタスクに必要な最小限の変更にとどめる」という方向の指示で抑制できる。

### サブエージェントとツール使用

Claude 4.6はサブエージェントを過剰に使う傾向がある。「単純なタスクは直接実行し、並列実行できる独立したタスクにのみサブエージェントを使う」のような指示が有効。

並列ツール呼び出しについては、「依存関係のないツール呼び出しは並列実行する」と明示すると効率が上がる。

### ハルシネーションとテスト

コードについて回答する前にファイルを読むよう促す指示があると、推測ベースの回答を防げる。
テストに過集中してハードコーディングで通そうとする傾向も、「一般的な入力に対して正しく動作する実装を」と指示することで抑制できる。

### 自己チェック

「最終回答の前に検証基準に照らして確認する」という指示は、特にコーディングや数学のタスクで効果的。

## 出力フォーマット制御

### プロンプトスタイルと出力スタイルの一致

Claudeの出力フォーマットは、プロンプト自体のフォーマットに影響される。markdownを減らしたいなら、プロンプト側のmarkdownも減らす。箇条書きを減らしたいなら、プロンプトを散文で書く。

### 構造の指定方法

出力構造の指定にはいくつかの手段がある:
- XMLタグで出力セクションを指定する（`<answer>` タグ内に回答を書くよう指示）
- structured outputs（APIの場合、JSONスキーマで制約）
- ツール呼び出し（分類タスクではenumフィールドが有効）
- few-shot examples（3〜5個の多様な例で出力パターンを示す）

## 長文コンテキスト

### ドキュメント配置

長いドキュメントはプロンプトの上部に、クエリは末尾に配置する。テストでは最大30%の品質向上が確認されている。

### メタデータと引用

複数ドキュメントを扱う場合、`<document>` タグで囲み、`<source>` でメタデータを付与する。
「関連する引用を先に抽出してから回答する」という指示は、長文からの情報抽出精度を上げる。

## API呼び出しプロンプト

### prefillの廃止

Claude 4.6ではprefill（最後のassistantターンの事前入力）が非対応。代替手段:
- structured outputsでフォーマットを制約
- XMLタグで出力構造を指定
- 「前置きなしで直接回答する」と指示

### thinking制御

adaptive thinking（`thinking: {type: "adaptive"}`）が推奨。effortパラメータで思考の深さを制御:
- コーディング: medium〜high
- チャット・分類: low〜medium
- 複雑な推論: high〜max

思考が過剰な場合は「アプローチを選んだら迷わず進める。新しい矛盾する情報が出ない限り判断を見直さない」のような指示が有効。
