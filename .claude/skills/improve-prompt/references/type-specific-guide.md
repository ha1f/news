# プロンプト種類別の改善ガイド

対象の種類に応じて追加で確認する観点。関連する節だけ使う。モデル世代・API 仕様に触れる点は model-notes.md が正。

## エージェント向けプロンプト

長時間の自律動作が前提。通常のプロンプトにない観点:

- **ゴール指向**: 手順の列挙でなくゴールと成功条件を書く（手順で縛ると、モデルが賢くなっても実行が古いまま）
- **自律性の較正**: 破壊的・不可逆な操作だけ確認を求め、可逆な操作は自律で進める設計か。止まる条件は 1 文の原則で書ける（model-notes.md 参照）
- **長時間実行の定石**: 「一度に 1 機能」「セッション開始時に状態確認（進捗ファイル・git log）、終了時に clean state（commit + 進捗更新）」
- **コンテキスト維持の 3 点セット**: compaction（設計判断と未解決事項を残す）・note-taking（外部ファイルへのメモ）・subagent 隔離（コンテキストを食う作業を任せ結論だけ受け取る）
- **検証の強制**: 「人間と同じ手順で end-to-end 確認してから完了報告」。進捗報告は tool result と突き合わせる（fabrication 防止）
- **オーバーエンジニアリング抑制**: 「現在のタスクに必要な最小限の変更にとどめる。仮定の将来要件のために設計しない」

## スキル (SKILL.md)

出典: https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices

- **description が発火の全て**: 「何ができるか + いつ使うか」を三人称で書く（system prompt に注入されるため。最大 1024 文字）。それだけ読んで発火判断できるか
- **progressive disclosure**: ① name + description（常駐）→ ② SKILL.md 本文（発火時）→ ③ references（必要時のみ）。本文に③へ追い出せる詳細が居座っていないか。本文 500 行以下、参照の深さは 1 段まで、100 行超の参照ファイルには冒頭に目次
- **Claude は既に賢い前提**: 知らない情報だけ足す。各段落に「token コストに見合うか」を問う
- **決定的処理はスクリプトへ**: 実行するのか参照として読むのかをスクリプト側に明示する
- **自由度の設計**: 壊れやすい手順（migration 等）は正確なコマンドで縛り、判断タスク（レビュー等）は基準だけ与えて任せる。テンプレも厳格（「この構造をそのまま使う」）か柔軟（「妥当なデフォルト。判断で調整」）か明示
- **時限情報を本文に書かない**: 日付依存の情報は隔離ファイルか「old patterns」節へ（腐った情報が本文に残る事故を防ぐ）
- **用語は概念ごとに統一**: field / box / element のような同一概念の表記揺れは解釈を割る

## ツール記述 (tool description)

出典: https://www.anthropic.com/engineering/writing-tools-for-agents

ツールは ACI (Agent-Computer Interface) であり、プロンプト本体と同格以上の改善対象（公式は SWE-bench でプロンプトよりツール改善に時間をかけたと明言）。小さな記述改善が劇的に効く。

- ツール間の役割が重複せず、どの場面でどれを使うか一意に決まるか（人間のエンジニアが即答できないなら曖昧）
- 返り値は high-signal か: UUID の羅列でなく意味のある情報を返す。pagination / truncation に妥当なデフォルトを持つ
- パラメータ設計で間違えにくくする（poka-yoke）。厳密な行数カウント等のフォーマット負荷をモデルに課さない

## 出力フォーマット制御

- プロンプトのスタイルは出力に伝染する: markdown を減らしたいならプロンプト側の markdown も減らす
- 手段の優先順: structured outputs（API、スキーマ制約）> XML タグでの出力構造指定 > few-shot。分類タスクは tool の enum フィールドが確実
- prefill は現行モデルで廃止（model-notes.md 参照）。「前置きなしで直接回答する」等の指示で代替

## 長文コンテキスト

- 長いドキュメントは上部、クエリ・指示は末尾に置く（公式テストで最大 30% の品質向上）。複数ドキュメントは `<document>` タグ + `<source>` メタデータで区別
- 「関連する引用を先に抽出してから回答する」で長文からの抽出精度が上がる

## API 呼び出しプロンプト

- thinking の深さは effort で制御（low〜max、現行仕様と用途別推奨は model-notes.md）。過剰なら「アプローチを選んだら迷わず進める。矛盾する新情報がない限り判断を見直さない」を添える
- sampling params での挙動調整は現行モデルで不可（model-notes.md 参照）。プロンプトで制御する
