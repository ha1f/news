プロンプト（SKILL.md、CLAUDE.md、`.claude/rules/` と `.claude/notes/` 配下、スクリプトの docstring や usage 等、エージェントが読んで従うテキスト）を編集したら、次の基準で `/improve-prompt` を実行する。

判定は編集量でなく**何を編集したか**で、節単位（節が無ければ段落単位）に行う。1節でも手順・指示を変えていれば1行でも実行する。説明・背景・理由だけなら不要。ただし手順が成り立つ前提の事実（コマンドやパスの実在等）を直したときは、手順を変えたものとして扱う。`improve-prompt` が軽微と判断して検証を提案しなくても、この基準を優先する。

手順・指示を変えたときは、`/improve-prompt` の改訂版に対して机上シミュレーションまで通す。該当節に**先行ステップ・その出力を使う後続ステップ・その節を参照している他ファイルの記述**を添えて fresh context の subagent に渡し、そのとおり実行するつもりで詰まる所・複数に読める所を報告させる（前提を欠くと偽の詰まりが、参照元を欠くと契約の破壊の見落としが出る）。read-only で実コマンドは走らせず、走らせないと確かめられない点は「未確認」として報告させる。条件付きの動作（「〜したときは〜する」）を書いた節には、発火させる編集を仮のシナリオとして3件以上与える。報告された詰まりを直したら机上だけ回し直し、2周しても残るなら PR 本文（PR が無ければ作業の報告）に書いて人間に委ねる。

「手順どおりに実行できない」「同じ節の中で指示と説明が矛盾する」は、diff と主張を突き合わせるレビューでは捕まらない。
