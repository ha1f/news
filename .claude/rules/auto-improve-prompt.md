プロンプト（SKILL.md、CLAUDE.md、`.claude/rules/` 配下、`.claude/notes/` 配下、スクリプトの docstring や usage 等、エージェントが読んで従うテキスト）を編集したら、`/improve-prompt` を実行して品質を確認する。

実行するかは編集量でなく**何を編集したか**で決める。判定は変更した箇所ごとに行い、1箇所でも手順・指示を変えていれば1行でも実行する。説明・背景・理由・事実の記述だけなら不要。`improve-prompt` 側の「軽微な変更には検証を提案しない」よりこちらを優先する。

手順・指示を変えたときは机上シミュレーションまで通す。改訂後の該当箇所に**前提となる先行ステップと、その箇所を参照している他ファイルの記述**を添えて fresh context の subagent に渡し、そのとおり実行するつもりで詰まる所・複数に読める所を報告させる（read-only。実コマンドは走らせない）。前提を欠くと抜き出し方に由来する偽の詰まりが出て、参照元を欠くと契約の破壊を見逃す。条件付きの動作を書いた箇所（「〜したときは〜する」）は、発火させる編集を仮のシナリオとして複数与えないと何も実行できない。報告された詰まりは直して回し直し、2周しても残るなら PR 本文に書いて人間に委ねる。

「手順どおりに実行できない」「同じ節の中で指示と説明が矛盾する」は、diff と主張を突き合わせるレビューでは捕まらない。
